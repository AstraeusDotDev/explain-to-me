### Socket compatibility finding and fix

The initial prepared short-name fix allocated a bare `s` basename. A real model build failed startup because the installed llama-server recognizes Unix host paths only when they end in `.sock`, as documented by its own `--help`.

The final allocator uses a random private `d-` directory and `s.sock`, retains the 100-byte guard and owned cleanup, and has a suffix regression assertion. The assertion failed before the correction. A successful real build exercised a temporary root where the old candidate path was 103 bytes and the new one was 94 bytes. An oversized root is still refused without deleting an unrelated marker file. No TCP fallback or global temporary-directory change was introduced.
